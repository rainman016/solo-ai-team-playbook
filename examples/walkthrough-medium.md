# 示例：一件中档需求从提出到收口

> 虚构场景，用来演示 `PLAYBOOK.md` 的流转。项目：一个个人博客（代码项目）。窗口：总控窗口 `★ [博客] 总控`（Claude Code，在项目 `总控台/` 子文件夹开窗）+ 产品经理窗口（需要时新开）+ Codex 作为施工方。文中 `→` 开头的是窗口回给 owner 的原话。

## 文件布局

```text
总控台/CLAUDE.md                  ← 导入总控专用规则（照 templates/lead-desk-CLAUDE.md）
项目状态.md                       ← 唯一状态文件（只有总控写），开头一行写总控会话编号
任务/站内搜索/方案.md              ← 产品经理窗口产出，含“owner 确认记录”
任务/站内搜索/任务包.md            ← 总控写，施工方只认这份
任务/站内搜索/回报.md              ← 施工方覆盖式写
任务/站内搜索/验收.md              ← 产品经理窗口产出，含手测记录
```

## 1. 提需求

owner 对总控说：“博客想加个站内搜索。”

## 2. 定档，回一行路由

```text
→ 中档／产品经理卡／新开产品经理窗口。原因：新功能，不涉及权限、数据迁移和外部接口。
```

owner 没叫停，继续。（如果 owner 回“这个很简单”，总控可以降为小档；拿不准就保持中档。）总控不自己装载产品经理卡，新开窗口 `↳ [博客] 产品经理·站内搜索`，brief 只写：装载 `roles/product-manager.md`、需求原话所在文件、产出写到 `任务/站内搜索/方案.md`、总控编号在 `项目状态.md` 开头、可用运行资源：无。产品经理窗口读完回“【已接】站内搜索·方案｜从现有导航和文章数据开始｜预计 1 小时后回报”，总控把任务池里这一行改成“在途”。

## 3. 出方案，owner 去产品经理窗口确认

产品经理窗口写 `方案.md`（方案摘要、确认清单、验收标准），然后给总控发一行：

```text
【待决定】站内搜索·方案｜需 owner 到本窗口确认 3 项（含花钱 0 项）｜回报：任务/站内搜索/方案.md
```

总控不转述方案内容，只告诉 owner 去哪：

```text
→ 站内搜索的方案好了：请到 💬 [博客] 产品经理·站内搜索 定 3 项（不涉及花钱）。
```

并把那个窗口标成 `💬`。owner 在产品经理窗口里边看依据边定：

```text
确认清单（带推荐默认值）：
1. 搜不搜正文？推荐：不搜（正文搜索需要建索引，范围变大）。
2. 空结果显示什么？推荐：“没有找到相关文章”+ 最新 5 篇。
3. 手机端要不要？推荐：要，搜索框收进菜单。

验收标准：
- [ ] 输入“缓存”，标题或标签含“缓存”的文章全部出现，且不超过 20 条
- [ ] 结果按发布时间倒序
- [ ] 输入不存在的词，显示“没有找到相关文章”和最新 5 篇
- [ ] 手机宽度（375px）下，搜索框在菜单里可用
- [ ] 现有页面的加载时间不变慢（用同一台机器对比前后）
```

owner 追问了一句“正文搜索会慢多少”，看完产品经理给的估算后回：“1 改成搜正文，其他按推荐。”
→ 最新反馈替代旧理解：产品经理把方案改为“标题 + 标签 + 正文”，验收标准第 1 条同步改，并在 `方案.md` 里逐项写“owner 确认记录”（项｜所选｜原话｜日期）——“其他按推荐”也拆成第 2、3 项各记一行。然后改回 `↳`，给总控发：

```text
【完成】站内搜索·方案｜已确认 3 项｜记录：任务/站内搜索/方案.md
```

总控派一个子代理读产品经理窗口里这段记录，只认 owner 本人的发言，回“通过”，才往下排。

> 为什么不在总控窗口问：总控一转述，方案细节就进了总控的上下文；owner 想追问“会慢多少”，总控也答不上来。“同意开工”也不等于方案已确认——这一步拦下了“搜不搜正文”这个会让范围翻倍的分歧。

## 4. 写任务包，做开工就绪检查（总控本职）

总控按 `templates/task-package.md` 写 `任务包.md`：目标、起点版本 `main@3f2a1c0`、引用 `方案.md` 的验收标准、范围（只做搜索，不改文章页样式；不合并、不推送）、可自行处理的情形（组件命名、样式细节）、停止条件、验证顺序（先跑搜索相关测试，再跑全量）。

开工就绪检查四项都勾上才派单（写入范围：`components/search/`、导航组件；任务池里没有其他在途线改这两处）。

## 5. 派单

总控后台派给 Codex，输出重定向到日志，并挂一个监视（回报文件一更新、或 4 小时没动静就唤醒总控）。brief 只写五样：

```text
装载：开发工程师卡（roles/developer.md）
可用运行资源：本机，测试只跑搜索相关用例，无独占要求
输入：任务/站内搜索/任务包.md
产出：任务/站内搜索/回报.md
总控编号：项目状态.md 开头
```

Codex 启动后日志有了第一行，总控把任务池里这一行从“已派未接”改成“在途”（派给窗口的话，要等对方回“【已接】站内搜索｜从搜索组件开始｜预计 2 小时后回报”）。

## 6. 回报（开发工程师卡）

```text
- 结论：搜索功能已实现，验收标准 5 条中 4 条自测通过
- 版本：a1b2c3d
- 已验证：第 1、2、4、5 条 — 证据：test-results/search.txt、screenshots/mobile.png
- 未验证：第 3 条（空结果的“最新 5 篇”依赖线上数据，本地数据只有 3 篇）
- 失败项：无
- 运行的退出证据：测试进程已结束，没有新建临时资源
- 待决定事项：无
```

## 7. 验收和手测（产品经理窗口）

总控把回报路径交给产品经理窗口。产品经理逐条对照，写 `验收.md`：第 3 条在测试数据补到 6 篇后复验，空结果只显示了 3 篇，**未通过**。

→ 返修第 1 轮：Codex 修复，回报版本更新为 `e4f5g6h`；复验第 3 条通过。（若同一条 2 轮仍不过，就重写任务包或退回方案层，不在原对话里继续磨。）

要 owner 手测时，产品经理窗口再发【待决定】，总控指引 owner 过去；owner 在那里手测、提反馈，产品经理逐项记进 `验收.md`，写完发【完成】。

## 8. 总控核证据

只核两件事：证据齐不齐、是不是同一版本。回报、验收和手测记录的证据路径都在，都对应 `e4f5g6h` ✓。总控不打开证据亲手再测一遍。

## 9. 门禁（总控窗口）

```text
→ 搜索已验收、手测通过（版本 e4f5g6h）。门禁：合并到 main 请在本窗口回“确认合并”；推送上线另行确认。
```

owner 回“确认合并”→ 总控合并。推送上线是下一道门禁，owner 没说之前不推。“好的”“可以”不算授权；owner 如果在产品经理窗口说“合并吧”，产品经理会请他到总控窗口再说一次。

## 10. 收口

总控当轮更新 `项目状态.md`：把“站内搜索”这一行移到“最近完成”（7 天后删），在决策记录里加一句“搜索范围含正文（owner 确认）”。产品经理窗口标 `✅`，总控提醒 owner 归档。

---

## 对照：小档怎么走

owner：“关于页有个错别字。”

```text
→ 小档／开发工程师卡／Codex。原因：范围清晰，不改需求。
```

总控直接写任务包（需求和验收标准就一句话：“关于页第二段‘份内’改为‘分内’，其他不变”），派单 → 回报 → 总控核证据 → 需要手测的话 owner 在总控窗口回一句 → 门禁授权。不开产品经理窗口、不走产品经理验收。
