# 示例：一件中档需求从提出到收口

> 虚构场景，用来演示 `PLAYBOOK.md` 的流转。项目：一个个人博客（代码项目）。窗口：一个总控窗口（Claude Code）+ Codex 作为施工方。文中 `→` 开头的是窗口回给 owner 的原话。

## 文件布局

```text
项目状态.md                      ← 唯一状态文件（只有总控写）
任务/站内搜索/方案.md             ← 产品经理卡产出
任务/站内搜索/任务包.md           ← 总控写，施工方只认这份
任务/站内搜索/回报.md             ← 施工方覆盖式写
任务/站内搜索/验收.md             ← 产品经理卡产出
```

## 1. 提需求

owner 对总控说：“博客想加个站内搜索。”

## 2. 定档，回一行路由

```text
→ 中档／方案阶段／产品经理卡／总控自己装载。原因：新功能，不涉及权限、数据迁移和外部接口。
```

owner 没叫停，继续。（如果 owner 回“这个很简单”，总控可以降为小档；拿不准就保持中档。）

## 3. 出方案和验收标准（产品经理卡）

总控装载产品经理卡，写 `方案.md`，交给 owner 的是摘要和确认清单：

```text
方案摘要：顶部导航加搜索框，按标题和标签搜索，结果最多 20 条，按发布时间倒序。

确认清单（带推荐默认值，你只需改不同意的）：
1. 搜不搜正文？推荐：不搜（正文搜索需要建索引，范围变大）。
2. 空结果显示什么？推荐：“没有找到相关文章”+ 最新 5 篇。
3. 手机端要不要？推荐：要，搜索框收进菜单。

验收标准：
- [ ] 输入“缓存”，标题或标签含“缓存”的文章全部出现，且不超过 20 条
- [ ] 结果按发布时间倒序
- [ ] 输入不存在的词，显示“没有找到相关文章”和最新 5 篇
- [ ] 手机宽度（375px）下，搜索框在菜单里可用
- [ ] 现有页面的加载时间不变慢（用同一台机器对比前后）
```

owner 回：“1 改成搜正文，其他同意。”
→ 最新反馈替代旧理解：方案改为“标题 + 标签 + 正文”，验收标准第 1 条同步改。总控回一行“方案已按第 1 条更新”，owner 确认。

> 为什么不直接开工：“同意开工”不等于方案已确认。这一步拦下了“搜不搜正文”这个会让范围翻倍的分歧。

## 4. 写任务包，做开工就绪检查（总控本职）

总控按 `templates/task-package.md` 写 `任务包.md`：目标、起点版本 `main@3f2a1c0`、引用 `方案.md` 的验收标准、范围（只做搜索，不改文章页样式）、可自行处理的情形（组件命名、样式细节）、停止条件、验证顺序（先跑搜索相关测试，再跑全量）。

开工就绪检查四项都勾上才派单（写入范围：`components/search/`、导航组件；任务池里没有其他在途线改这两处）。

## 5. 派单

派给 Codex 的 brief 只写三样：

```text
装载：开发工程师卡（PLAYBOOK.md 附录 A）
输入：任务/站内搜索/任务包.md
产出：任务/站内搜索/回报.md
```

## 6. 回报（开发工程师卡）

```text
- 结论：搜索功能已实现，验收标准 5 条中 4 条自测通过
- 版本：a1b2c3d
- 已验证：第 1、2、4、5 条 — 证据：test-results/search.txt、screenshots/mobile.png
- 未验证：第 3 条（空结果的“最新 5 篇”依赖线上数据，本地数据只有 3 篇）
- 失败项：无
- 待决定事项：无
```

## 7. 验收（产品经理卡）

总控装载产品经理卡，逐条对照，写 `验收.md`：第 3 条在测试数据补到 6 篇后复验，空结果只显示了 3 篇，**未通过**。

→ 返修第 1 轮：Codex 修复，回报版本更新为 `e4f5g6h`；复验第 3 条通过。（若同一条 2 轮仍不过，就重写任务包或退回方案层，不在原对话里继续磨。）

## 8. 总控核证据

只核两件事：证据齐不齐、是不是同一版本。回报和验收的证据都对应 `e4f5g6h` ✓。总控不亲手再测一遍。

## 9. owner 手测和门禁

```text
→ 搜索已验收通过（版本 e4f5g6h），请你手测。门禁：合并到 main 请回“确认合并”；推送上线另行确认。
```

owner 手测后回“确认合并”→ 合并。推送上线是下一道门禁，owner 没说之前不推。“好的”“可以”不算授权。

## 10. 收口

总控当轮更新 `项目状态.md`：删掉“站内搜索”这一行，在决策记录里加一句“搜索范围含正文（owner 确认）”。

---

## 对照：小档怎么走

owner：“关于页有个错别字。”

```text
→ 小档／任务包／开发工程师卡／Codex。原因：范围清晰，不改需求。
```

总控直接写任务包（需求和验收标准就一句话：“关于页第二段‘份内’改为‘分内’，其他不变”），派单 → 回报 → 总控核证据 → 门禁授权。不出方案、不走产品经理验收。
