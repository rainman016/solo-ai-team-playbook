# 跨账号接力

- **原理**：对话不能跨账号，项目文件和 Git 可以。另一个账号只靠“交接载体 + Git 现状”接续工作，不靠聊天记录。
- **交接载体以项目为准**：项目 `AGENTS.md` / `CLAUDE.md` 已规定交接文件的，一律用项目规定的载体和格式，不另建文件。项目没有交接机制时，才在根目录建 `HANDOFF.md` 兜底。
- **兜底 `HANDOFF.md` 写法**：覆盖式更新，每节只留：目标与验收标准、进度（已验证 / 未验证 / 进行中）、下一步（可直接执行的粒度）、关键决策及原因、改动文件、待 owner 确认与风险。默认不提交到 Git。
- **安全**：任何交接载体都不得写入密钥、token、密码或其值（遵守你自己的密钥红线）。
- **接手指令**：`接力：<原窗口标题>`。收到后：
  1. 按项目规则找到该工作线的载体，只读该项及其指向的必要来源；同时看 `git status` 和最近几条 `git log`，与载体核对，不一致时以实际文件为准，并按项目规则修正载体。
  2. 标题由总控改：接手窗口不自己改标题，也不给原窗口标 `✅`；接手的是总控本人时照旧用 `★ [项目] 总控`（不加后缀）。没有总控的单窗口项目，按CLAUDE-snippet.md 命名规范给新窗口起标题。
  3. 用 3 行以内回报：目标、当前进度、马上要做的下一步。
  4. 没有待 owner 确认的事项就直接继续；有则只问那一项，不依赖它的事照常推进。接手的是总控时，先确认原总控已停或已交接（同一项目同一时间只有一个项目总控，做法见`rules/lead.md`“额度与接力”），再按任务池恢复在途线；跨账号时旧账号的在途窗口视为停在额度上，按其交接文件在新账号重新派出。授权以项目登记和 owner 的原话为准，不因换账号重新确认已授权的事，也不把换账号当成新的授权。
  5. 没写窗口标题，或找不到对应载体时，列出载体中正在进行的工作线请 owner 选一条，不全项目扫描去猜。
- **多窗口项目**：载体写法和子窗口规则见 `~/.claude/solo-ai-team-playbook/CLAUDE-snippet.md`；总控接力见`rules/lead.md`“额度与接力”。
