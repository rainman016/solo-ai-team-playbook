# 协作共用规范（岗位卡引用，需要时读）

- **验收标准写法**：每条都能判断通过或不通过；写明用什么数据、在哪里看；不写“体验良好”“合理”这类无法判断的词。
- **回报格式**：结论一句 → 版本（提交号或文件） → 已验证（附证据路径） → 未验证 → 失败项 → 待决定事项（每项标“简单拍板”或“需讨论”）。
- **证据要求**：只给路径，不贴全文；所有证据对应同一版本；没亲自看过的写“未验证”。
- **文件位置**：任务包、回报、结论文件放在哪里，由项目规定。
- **接单与完成通知**：见通用规则“接单与通知”。
- **协商记录**（方案文件里的一节，总控对方案提了意见时写）：总控意见一句（附意见文件路径）｜本窗口意见一句｜合并后的改法｜未谈拢的点｜推荐。一轮＝总控交一次意见文件、本窗口回一次合并结果。最多 2 轮；第 2 轮仍有未谈拢的点，就在【待决定】里写“含 N 项分歧”，由 owner 在本窗口定。
- **找 owner 的方式**（子窗口这一侧）：
  - **怎么分**：看 owner 是否需要看材料、追问才能定。不需要的是简单拍板（选哪个、同不同意、施工中新增的费用、门禁授权），写进回报交总控。需要的是需讨论（需求、方案、原型、验收与手测，以及随需求或方案提出的花钱），按下面的流程走。类别由子窗口在回报里标出，总控最终判定。
  - **请求**：发【待决定】通知，结论写“需 owner 到本窗口确认 N 项（含花钱 M 项；协商后改的 K 项；分歧 J 项；没有的写 0）”，然后等总控指引 owner 过来。
  - **确认**：
    - owner 来后，边看依据边定。不放一键拍板按钮。owner 说“全部按推荐”算逐项确认，也要逐项记下；涉及花钱或撤不回的项单独再确认一次。
    - 在方案或回报文件里写一节“owner 确认记录”，一项一行：项｜所选｜原话｜日期。
    - 按 owner 所选更新方案和验收标准；超出本次确认清单的变化只转总控、不改。
  - **收尾**：改回 `↳`，发【完成】通知“已确认 N 项｜记录：路径”。
  - **小档没有产品经理**：手测结果由 owner 在总控窗口回一句，按简单拍板处理。
